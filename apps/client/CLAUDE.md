# Client CLI

`@skysend/client` - the end-user CLI, shipped as `skysend`. Commander for flags, Ink (React in the terminal) for the interactive TUI, `@skysend/crypto` for everything cryptographic. Compiled to a standalone binary with Bun.

This is an **untrusted-server client**, exactly like the browser. It encrypts before uploading and decrypts after downloading, and it must never send the secret, a derived key, or a plaintext filename to a server.

## Layout

```
src/index.ts       Commander wiring. Every command registers itself here.
src/commands/      One file per command, each exporting register<Name>Command(program)
src/lib/           api client, auth, config, history, oidc, progress, upload-job, download-job, inbox-job,
                   instances, clipboard, paths, ssh-keygen, terminal, filename
src/tui/           Ink app: App.tsx, shell.tsx, views/, components/, theme.tsx, types.ts
src/version.ts     Auto-generated by scripts/toolbox/version.mjs - never edit by hand
```

Commands: `upload` (`--to` sends into a file request), `download`, `note`, `note-view`, `inbox`, `ls`, `delete`, `config`, `auth`, `update`, `interactive`. Running `skysend` with no arguments starts the TUI.

ESM with `.js` extensions on relative imports.

## Adding a command

1. Create `src/commands/<name>.ts` exporting `register<Name>Command(program: Command)`.
2. Register it in `src/index.ts` in the order it should appear in `--help`.
3. Support `--server` and `--json` if the command produces output a script might consume.
4. Resolve the server through `resolveServer()` from `lib/config.ts`, never a hardcoded URL or a bare `process.argv` read.
5. Throw `ApiError` for HTTP failures - `src/index.ts` catches, prints the message, and exits 1.
6. Add the command to `docs/user-guide/client-cli/commands.md`.

## Parity with the web app

The CLI speaks the same API and the same crypto as the SPA, so a change on one side usually needs the other:

| Concern | Web | Client |
| :--- | :--- | :--- |
| API client and schemas | `@skysend/transfer`, bound in `lib/api.ts` | `@skysend/transfer`, bound by `apiFor(server)` in `lib/api.ts` |
| Upload and download | `uploadEncrypted` and `decryptedStream` of `@skysend/transfer` in `lib/upload-worker.ts` and `hooks/useDownload.ts` | the same functions in `lib/upload-job.ts` and `lib/download-job.ts` |
| Links | `buildShareLink` of `@skysend/transfer` | `buildShareLink` and `parseShareLink` of `@skysend/transfer`, which opens file and note links only |
| Local history | IndexedDB (`lib/upload-store.ts`) | `~/.config/skysend/history.json` (`lib/history.ts`) |
| Password KDF | hash-wasm Argon2id | its own `Argon2idHashFn` |
| File requests | `openRequestLink`, `openInbox`, `readInboxNote` of `@skysend/transfer` in `useRequestUpload` and `useInbox` | the same functions in `lib/upload-job.ts` (`openRequest`, `runRequestUpload`) and `lib/inbox-job.ts`. Making a request stays in the web, and a request that asks for a note is left to the browser, since the web sends files and note as one submission |
| Notes | `createEncryptedNote` and `openNote` of `@skysend/transfer` in `useNoteUpload` and `useNoteView` | the same functions in `commands/note.ts`, `tui/views/NoteCreate.tsx` and `NoteView.tsx` |
| Note format | `@skysend/note-format` in `useNoteUpload` | `@skysend/note-format` through `lib/note.ts` |

`skysend note` creates a note of one block, the Note tab of the TUI one of several parts (`MAX_BLOCKS` at most). `prepareNote()` sends the blocks as `blocks` to a server that reports `noteBlocks`, and a single block in the legacy format to an older one, where the TUI offers no second part. That fallback, `toLegacyNote()`, is marked `LEGACY(notes-v1)` and goes with the legacy content types.

Web and CLI share one API client, `createApiClient` in `packages/transfer/src/api.ts`, which parses every response with Zod. The CLI talks to servers of every version, so a field the server gains goes there with `.optional().default(...)` or `.catch(...)`. `apiFor(server, oidcToken)` passes `forTerminal` as `cleanMessage`, so every `ApiError` arrives with the server's message already disarmed, and sends the OIDC token only to the routes that create something.

## Local state

Config and history live under `$XDG_CONFIG_HOME/skysend/` or `~/.config/skysend/`:

- `config.json` - saved servers, default server, per-server WebSocket flag, stored OIDC token
- `history.json` - uploads and notes created from this machine, including `ownerToken` so `delete` works

Both files hold owner tokens. Never print their raw contents in a log line or an error, and never sync them anywhere. Every file in that folder is written through `writePrivateFile()` from `lib/private-file.ts`: mode `0600` in a `0700` folder, narrowed with `chmod` when an older version left it wider (GHSA-5vjq-2637-p33f).

## OIDC

`lib/oidc.ts` runs a loopback HTTP listener, opens the browser, and stores the resulting JWT. The listener answers only on `/callback/<32 random bytes>`, which goes to the server as `cli_callback`, since any local program or web page can reach the port. `openBrowser` opens http and https only, and on Windows through `rundll32 url.dll,FileProtocolHandler`, never `cmd /c start`: cmd.exe reads `&` and `|` in an address as its own syntax, and the address starts with a server from the public list or one typed in. Requests then send `Authorization: Bearer <token>`. The local JWT decode reads `exp` only and never verifies - the server re-verifies on every request, and the comment saying so should stay.

`ensureOidcAuth()` is the entry point commands use. Call it only where the server actually enforces auth (upload init, note creation), not on read paths.

## TUI

Ink 8, React 19, function components, full screen (`alternateScreen` in `commands/interactive.ts` and `note-view.ts`), painted in the dark Graphite colors of the web. The look follows the design canvas of 2026-10-17. The keys are the third try: number keys for tabs and tab for areas were rejected by the user as unusable, so every screen is now one list of rows with one cursor.

- **Every screen is a `Form`** (`components/Form.tsx`) of rows: `section`, `note`, `choice` (`‹ value ›`, ← → change it), `input` (takes typing and pastes while the cursor is on it), `button` (`primary` for the main action), `item` (an entry of a list, with enter, space, del, ← and →) and `editor` (`components/Editor.tsx`, several lines). The form owns the cursor, the keys, the scrolling and the key bar, so ↑ ↓ move, enter does what the row says, esc goes back and typing goes into the field everywhere alike. Do not add letter shortcuts or keys that only one screen knows, add a row instead.
- `App.tsx` is the shell: the welcome screen until a server is connected, then the tab bar, the tabs and the key bar. The tab bar is the top row: esc, or ↑ on a form's first row (`onExit`), moves the cursor there, ← → switch tabs, ↓ goes back in. `q` quits only from the tab bar, so a stray q never kills an upload, `ctrl+c` always. Every tab stays mounted inside React's `Activity`: a hidden tab keeps its state, its transfer runs on, and its effects, input included, are dropped while hidden.
- A screen over a tab (the file picker, the password and target steps of Receive, the note view) passes `upExits={false}`, so only esc leaves it. Buttons that throw work away ask for a second enter, like "Cancel the upload".
- `shell.tsx`: `useShell(hints, { typing })` is called by the form, `useFocus()` tells a tab whether it has the cursor and hands it up with `toTabs()`, `useRoom()` is the width and height a tab may fill, `useToast()` the message at the top right.
- `theme.tsx` holds the Graphite colors (`COLORS`, `page` included) and one accent: the server's `customColor`, SkySend green before a server is chosen. `useTint()` is the accent mixed into a card, the background of the row with the cursor. Every text sets its color, since the terminal's own may be dark.
- `components/Frame.tsx`: `Panel` is a filled card, its top and bottom edge half a row and its sides a full column of the card's color (a cell is twice as tall as wide, so this looks even), the corners quarter blocks. No colored frames for focus, the row with the cursor shows it. `LinkText` puts every wrapped line of a link into an OSC 8 hyperlink with the whole URL. `components/LinkReady.tsx` is the link with QR code and its buttons, shared by Send, Note and My links.
- No timer may render while a download runs. A render from `useAnimation` between two reads stalled downloads over loopback for seconds: the socket stayed unread at the wrong moment and the kernel kept the window shut (MSS 64 KiB on `lo`). The Receive spinner turns with the progress events, which come at most ten times a second.
- Layout is `<Box>` and `<Text>`, never raw ANSI escapes. The exceptions are OSC 8 in `LinkText` and OSC 52 in `lib/clipboard.ts`, which copying always sends besides a system tool, since a tool can copy on the wrong machine (Orca's terminals carry `DISPLAY=:99`, an invisible Xvfb).
- One column, at most 100 wide. The tabs in the header always show in full: when the row gets tight they move closer together, then the name of the instance is cut, down to the ◆, and the server shows only where it fits whole. Check a new screen at 80 by 30 and at 100 by 40, and drive it like a newcomer: arrows, enter, esc, space, typing and pasting only. Screenshots come out right from xterm.js, a conversion of the ANSI to HTML draws stripes and broken corners that no terminal shows.
- Progress rendering for non-TUI commands lives in `lib/progress.ts` (`renderProgress`, `writeProgress`, `clearLine`). Use it rather than a fresh `process.stdout.write` loop.
- `stubs/react-devtools-core` is a deliberate empty stub so the Bun binary does not pull in devtools. Leave it.

## Build

```bash
pnpm client:build        # crypto + tsc
pnpm client:run          # tsx src/index.ts, no build needed
pnpm client:compile      # single binary for the current platform
pnpm --filter @skysend/client build:all   # all five release targets
```

Targets: linux-x64, linux-arm64, macos-x64, macos-arm64, windows-x64. Anything that only works under Node and not under Bun breaks the shipped binary, so prefer Web APIs (`fetch`, `WebSocket`, Web Streams) over Node-specific ones where both exist.

`src/version.ts` is rewritten by `pnpm version:bump` and is what `--version` and the `update` command compare against.

## Output style

- `console.log` for normal output, `console.error` for failures. There is no logger here and none is wanted.
- `--json` prints one JSON object and nothing else. No progress bars, no decorations, no extra lines.
- Never print a secret, a share URL fragment on its own, or an owner token in a diagnostic message. The full share URL as the deliberate result of `upload` is the exception, because that is the whole point of the command.
- Text from another party goes through `forTerminal()` from `lib/terminal.ts` before it reaches the terminal: a sender's file name, a note, a server's error message or title, the name in a session token. Ink strips some escape sequences but passes OSC, which can write to the clipboard. `ApiError` cleans its message itself.

## Files on disk

- A file name from a sender goes through `sanitizeFilename()` from `lib/filename.ts` before it becomes a path, and `availablePath()` picks a name that does not replace an existing file. Only a path the user typed may overwrite.
- Plaintext never touches the disk on the way up. `upload-job.ts` reads each file through `fs.openAsBlob`, and several files go into the stored zip of `@skysend/transfer` while the upload reads them, so the memory stays flat whatever the size.
- A download writes into a hidden `.skysend-<uuid>.part` file next to its target and renames it at the end, so a cut download never looks complete. It waits for `drain`, so a slow disk does not fill the memory.

## Tests

Vitest in `apps/client/tests/`, run with `pnpm --filter @skysend/client test`. Coverage is scoped to `src/lib/**` and excludes `api.ts`, `auth.ts`, `upload-job.ts`, `download-job.ts`, `inbox-job.ts`, and `ssh-keygen.ts` - those need a live server or a browser-grade crypto environment. The upload, download and request logic itself is tested in `packages/transfer`, the CLI end to end in `e2e/tests/cli.spec.ts` and `e2e/tests/cli-requests.spec.ts`.

Pure helpers are the testable surface: config resolution, URL building, duration parsing, progress math, history handling, JWT expiry. `tests/commands/` checks how a command hands its flags to a job, with the job mocked. TUI views are not unit-tested.
