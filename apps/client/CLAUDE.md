# Client CLI

`@skysend/client` - the end-user CLI, shipped as `skysend`. Commander for flags, Ink (React in the terminal) for the interactive TUI, `@skysend/crypto` for everything cryptographic. Compiled to a standalone binary with Bun.

This is an **untrusted-server client**, exactly like the browser. It encrypts before uploading and decrypts after downloading, and it must never send the secret, a derived key, or a plaintext filename to a server.

## Layout

```
src/index.ts       Commander wiring. Every command registers itself here.
src/commands/      One file per command, each exporting register<Name>Command(program)
src/lib/           api client, auth, config, history, oidc, progress, url, ws-upload, ssh-keygen
src/tui/           Ink app: App.tsx, views/, components/, theme.tsx, types.ts
src/version.ts     Auto-generated by scripts/sync-version.sh - never edit by hand
```

Commands: `upload`, `download`, `note`, `note-view`, `ls`, `delete`, `config`, `auth`, `update`, `interactive`. Running `skysend` with no arguments starts the TUI.

ESM with `.js` extensions on relative imports.

## Adding a command

1. Create `src/commands/<name>.ts` exporting `register<Name>Command(program: Command)`.
2. Register it in `src/index.ts` in the order it should appear in `--help`.
3. Support `--server` and `--json` if the command produces output a script might consume.
4. Resolve the server through `resolveServer()` from `lib/config.ts`, never a hardcoded URL or a bare `process.argv` read.
5. Throw `ApiError` for HTTP failures - `src/index.ts` catches, prints the message, and exits 1.
6. Add the command to `docs/user-guide/client-cli/commands.md`.

## Parity with the web app

The CLI speaks the same API and the same crypto as the SPA, so a change on one side usually needs the other:

| Concern | Web | Client |
| :--- | :--- | :--- |
| API schemas | `apps/web/src/lib/api.ts` | `apps/client/src/lib/api.ts` |
| Upload transports | WebSocket with HTTP chunk fallback | same, `lib/ws-upload.ts` and `uploadHttpTransport` |
| Share URL shape | `hooks/useUpload.ts` | `lib/url.ts` |
| Local history | IndexedDB (`lib/upload-store.ts`) | `~/.config/skysend/history.json` (`lib/history.ts`) |
| Password KDF | hash-wasm Argon2id | its own `Argon2idHashFn` |

Both `api.ts` files parse responses with Zod. When the server adds a config field, add it to both schemas with `.optional().default(...)` so an old server still works.

## Local state

Config and history live under `$XDG_CONFIG_HOME/skysend/` or `~/.config/skysend/`:

- `config.json` - saved servers, default server, per-server WebSocket flag, stored OIDC token
- `history.json` - uploads and notes created from this machine, including `ownerToken` so `delete` works

Both files hold owner tokens. Never print their raw contents in a log line or an error, and never sync them anywhere.

## OIDC

`lib/oidc.ts` runs a loopback HTTP listener, opens the browser, and stores the resulting JWT. Requests then send `Authorization: Bearer <token>`. The local JWT decode reads `exp` only and never verifies - the server re-verifies on every request, and the comment saying so should stay.

`ensureOidcAuth()` is the entry point commands use. Call it only where the server actually enforces auth (upload init, note creation), not on read paths.

## TUI

Ink, React 19, function components. `App.tsx` owns view state, `views/` are the screens, `components/` are reusable widgets, `theme.tsx` provides the accent color pulled from the server's `customColor`.

- Layout is `<Box>` and `<Text>`, never raw ANSI escapes.
- Keyboard handling goes through `useInput`. Every view must handle escape or `q` to go back.
- Progress rendering for non-TUI commands lives in `lib/progress.ts` (`renderProgress`, `writeProgress`, `clearLine`). Use it rather than a fresh `process.stdout.write` loop.
- `stubs/react-devtools-core` is a deliberate empty stub so the Bun binary does not pull in devtools. Leave it.

## Build

```bash
pnpm client:build        # crypto + tsc
pnpm client:run          # tsx src/index.ts, no build needed
pnpm client:compile      # single binary for the current platform
pnpm --filter @skysend/client build:all   # all five release targets
```

Targets: linux-x64, linux-arm64, macos-x64, macos-arm64, windows-x64. Anything that only works under Node and not under Bun breaks the shipped binary, so prefer Web APIs (`fetch`, `WebSocket`, Web Streams) over Node-specific ones where both exist.

`src/version.ts` is rewritten by `pnpm version:bump` and is what `--version` and the `update` command compare against.

## Output style

- `console.log` for normal output, `console.error` for failures. There is no logger here and none is wanted.
- `--json` prints one JSON object and nothing else. No progress bars, no decorations, no extra lines.
- Never print a secret, a share URL fragment on its own, or an owner token in a diagnostic message. The full share URL as the deliberate result of `upload` is the exception, because that is the whole point of the command.

## Tests

Vitest in `apps/client/tests/lib/`, run with `pnpm --filter @skysend/client test`. Coverage is scoped to `src/lib/**` and excludes `api.ts`, `auth.ts`, `ws-upload.ts`, and `ssh-keygen.ts` - those need a live server or a browser-grade crypto environment.

Pure helpers are the testable surface: config resolution, URL building, duration parsing, progress math, history handling, JWT expiry. Commands and TUI views are not unit-tested.
